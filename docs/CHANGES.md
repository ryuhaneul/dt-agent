# DT Agent changes from ductor

DT Agent is a modified fork of [PleasePrompto/ductor](https://github.com/PleasePrompto/ductor), based on ductor v0.20.1 (MIT license, original copyright PleasePrompto). This document lists what the fork changes relative to the original; see the [README](../README.md) for installation and use.

## 1. Upstream base

DT Agent is based on ductor v0.20.1. The project metadata retains the PleasePrompto/MIT attribution and identifies [github.com/ryuhaneul/dt-agent](https://github.com/ryuhaneul/dt-agent) as the fork.

## 2. Repository, packaging, image and filesystem changes

| Change / interface | Behavior |
| --- | --- |
| Materialized source tree | Replaced the old vendored Git tree with the v0.20.1 source tree plus the fork features that were previously applied only at image build time. This exposes those changes in Git; it does not mean every added source line is a new runtime feature. |
| Direct-source image | Compose builds docker/ductor-bot/Dockerfile, which installs /app/src from the checkout instead of fetching a pinned upstream package and applying overlays at image build time. |
| Package metadata alignment | Project version was set to 0.20.1 (later 1.0.0, see Own version 1.0.0 below) and project URLs identify the fork; old root metadata said 0.19.0 despite the manifest targeting v0.20.1. Python remains >=3.11, hatchling/MIT attribution remain. |
| Container startup and safe defaults | The framework home link points to the persistent mount while existing directories are preserved with a warning. The example enables heartbeat and omits Claude browser integration. Onboarding refuses root and requires Python 3.9 or newer. A nonblocking home lock prevents concurrent bot processes and is released on exit or exec. |
| Home locking and verification portability | Startup retains locks for both environment and configured homes when they differ. Git push isolation tests generate temporary TLS certificates, and browser server lifecycle tests run in CI. Documentation covers onboarding UID/GID, proxy and CA restrictions, and disabling heartbeat. |
| Host authentication and maintenance | Claude always uses an explicit per-slot configuration directory from the bot home, including for project working directories, and its default link stays on the default slot. Codex uses device login and CLI logout while retaining sessions and configuration. Host home paths expand tildes, config updates are atomic, running turns use the stored envelope, Gemini OAuth files are recognized and removed on logout, and status runs Compose from the checkout with a separate Claude status line for each configured slot. |
| Account usage | Read-only Telegram `/usage` works on all agent bots with saved Claude values, on-demand Codex queries and in-place refresh; Grok automatic queries are unsupported. Main-only `/accounts` adds a saved usage line per slot. |
| Claude slot management | Main-only Telegram `/accounts` and host `logout.sh claude --prefer`, `--priority` and `--clear-cooldown` share slot rules. Host lists show remaining cooldowns without a container. Config and cooldown transactions preserve concurrent edits with file locks; login merges newly authenticated slots into the latest list. Priority reaches main within seconds and sub-agents at their next start; cleared cooldowns apply to all on the next call. |
| Claude transcript retention | The standard image validates and installs a root-owned managed drop-in setting cleanupPeriodDays to 36500 for every in-container Claude invocation and authentication slot. Higher-priority managed sources may supersede it; a later-named local drop-in is the deliberate override path. |
| Claude account rotation | Project, title and one-shot calls share bot-home authentication and cooldowns. Account lists and timezones update on reload; title parsing removes switch notices, and ordinary connection resets remain ordinary errors. |
| Rate limits, timezones and browser recovery | Claude rate-limit detection uses bounded phrases and excludes ordinary result text; slot home paths expand tildes. CLI and task timezone resolution share the configured/host/UTC policy. Browser disconnections clear all page state for recovery, health reports a failed browser launch, and the browser image uses a dependency lockfile and init without unused display or shared-memory settings. |
| Startup, authentication and tool safety | Claude calls without an account list and default logout explicitly use the default authentication slot. Rate-limit detection excludes disk quota and context exhaustion errors. Git pushes accept local branch names and use validated URLs and resolved commits from a temporary bare repository with an isolated configuration and environment. Home locking precedes startup writes; image users follow onboarding UID/GID. Browser recovery shares launch attempts, replaces crashed pages and reports launch failures through health. Secret fills use store values only on matching secure HTTPS origins; expired input remains quarantined through the grace period after restart, including non-secret commands, replies and captions while preserving guarded-quote protection. |
| Task resume delivery ordering | Follow-ups accepted during final result delivery start after the previous run ends, without overlapping executions. Duplicate pending resumes are refused; cancellation discards them and shutdown records them for the existing restart notice. |
| Maintenance and test isolation | Removed unused provider and process helpers, development runner and obsolete image settings. Git tests ignore inherited command-line configuration. |
| Secret tool boundaries | Documentation explains same-user file access. Browser secret fills require a matching secure origin and recheck it before assignment; fills run only on the secure page and all push URLs are validated. Git pushes disable hooks, enforce certificate verification and clear proxies, including URL-specific overrides. Secret store writes preserve symlinks and explicit store paths expand tildes. |
| Secret input interception | Exact case-insensitive commands, slash-prefixed values while waiting, a 120-second expiry grace period and deletion of guarded replies prevent unintended normal processing. Guard persistence retries are bounded, deletion retries run outside the input lock and secret store operations use worker threads. |
| Public project identity | The distribution is `dt-agent`; project links and Telegram info buttons point to the public repository, with no PyPI button. Author model wording and topic examples are updated, personal test terms and obsolete skip hashes are removed, unused screenshots and local ignore patterns are deleted, and bundled skills have third-party notices, including a bundled MIT notice for karpathy-guidelines. |
| Own version 1.0.0 | The project version, `ductor_bot.__version__` (printed by `ductor --version` as `DT Agent 1.0.0`) and the bug-report example are 1.0.0. The upstream baseline stays ductor v0.20.1 (see UPSTREAM.md). |
| CI gates and development checks | The Tests workflow fails on `mypy ductor_bot/` (strict, pinned `mypy==2.4.0`), the full pytest run (Python 3.11 and 3.12), `python -m ductor_bot.i18n.check`, `python scripts/build_agent_docs.py --check`, `scripts/tests` (Python 3.9 and 3.11) and `bash -n` of the tracked shell scripts. Ruff runs in a separate informational job with a pinned version (`ruff==0.16.9`) and does not fail the workflow. `CPY001` (copyright header) is ignored because the project uses no per-file headers. `just check` uses the same blocking checks; `just lint` is the informational ruff run. |
| Package payload boundary | The old unanchored `run.py` ignore pattern could also match a file inside the package; it is anchored to the repository root. |
| Explicit extras | DUCTOR_EXTRAS accepts a whole comma-separated list of matrix,slack,api; malformed or unsupported lists fail the image build. DUCTOR_BUILD_EXTRAS records it. The former paramiko-based ssh extra was removed; openssh-client is installed by default. |
| One container execution boundary | CLI providers execute directly in the bot container. The nested DockerManager/sandbox branch and Docker socket ownership logic are removed; the browser remains a separate compose service. |
| Container init and stop grace | Bot service has init:true and stop_grace_period:30s. |
| Restrictive clone umask | The image explicitly chmods its entrypoint to 0755 so a checkout made under restrictive umask remains executable. The image user is built with the onboarding account’s UID/GID (both default to 1000); root is not supported. |
| Startup PID and account state | Entrypoint preserves the PID file; the bot writes its own PID after acquiring the home lock. Entrypoint persists ~/.claude.json through /ductor/.cli-auth/claude.json. Authentication directory links still point into the mounted home. |
| Build-context exclusions | New .dockerignore excludes Git metadata, caches, local envs, tests/docs, overrides and local port/rollback files. Only the declared COPY inputs enter the bot package build. |
| Conditional host listeners | Onboarding generates compose.override.yml ports only for enabled API/webhook listeners from saved config, preserving a chosen bind address. Root compose has no unconditional host port publication. |
| Environment templates | Root .env.example is compose settings; docker/env/ductor.env.example is bot-only providers; docker/env/shared.env.example is browser token and timezone. |
| Git ignore cleanup | Obsolete overlay/build exclusions and the ambiguous run.py pattern are revised for a tracked direct-source package, with local env/rollback/build outputs kept out of Git. |
| Manual upstream integration | Automatic upstream-check workflow and overlay replay instructions are replaced with manual upstream release merges and explicit conflict review. |
| Fail-fast CLI installation and locale | Dockerfile removes ignored npm installation failures, sets C.UTF-8, and keeps procps for the container runtime. A failed CLI install now fails the build. Grok image-owned binary relocation was already present and is retained. |
| Single-container PID contract | run_bot no longer kills another live PID holder; it rejects duplicate startup. PID equal to the current process is treated as stale, and the entrypoint handles previous-container PID cleanup. One home shared by concurrently running bot containers is unsupported. |
| Carried Claude authentication/rotation | Multi-account CLI auth/slot cooldown and rotation code plus settings/project sharing are part of the tracked source. This is carried fork behavior. |
| Carried Telegram media/streaming | Media retry/caption fallback, streaming completion notification and send retry adjustments are part of the tracked source. The inter-agent retry contracts in section 5 are separate. |
| Carried heartbeat feature patches | ACK suspension, the preserved session model, automatic target/dormancy/wake state and topic-busy behavior are tracked source/tests. |
| Carried workspace tools and locale | Browser tool/rules, bundled coding skill, persona prompt support and Korean translations are retained in the assembled package tree rather than a separate overlay/feature-adapt directory. |
| Dependency lock retirement | uv.lock is deleted. Installation uses declared pyproject dependencies and chosen extras; a future build resolving ranges and unpinned npm CLIs is not guaranteed bit-identical. |
| Default OpenSSH client | openssh-client is always installed in the bot image, supplying ssh/scp. Python paramiko is absent; PyNaCl remains in api because API encryption uses it. No SSH server or host port is enabled by this change. |
| Retired SSH extra/input rejection | Remove ssh from optional/dev dependencies and the build allowlist, onboarding SSH question/options and extras assembly. DUCTOR_EXTRAS=ssh, --ssh/--no-ssh and a present ONBOARD_SSH fail explicitly with "ssh extra was removed; openssh-client is included in the image by default". |
| Host timezone default | First-install precedence: --tz, ONBOARD_TZ, host detection, UTC. On reruns, saved user_timezone precedes host detection. Detection validates TZ, /etc/timezone and the /etc/localtime zoneinfo symlink suffix with ZoneInfo in that order; the interactive question shows the detected default. Tests inject detection paths and cover priority/fallback and retired SSH input failures. |

## 3. Installation and operator scripts

| Change / interface | Behavior |
| --- | --- |
| onboard.sh | Changed wrapper: checks Docker/Compose availability and delegates all arguments to onboard.py. Old counterpart was the Bash onboarding script; it is not the deleted ductor init wizard. |
| onboard.py | New parser/writer. Flags: --no-prompt, --home, --telegram-token-file, --allowed-users, --allowed-groups, --tz, --language, repeatable --transport none/matrix/slack; --matrix-homeserver/--matrix-user-id/--matrix-password-file/--matrix-access-token-file/--matrix-device-id/--matrix-allowed-rooms/--matrix-allowed-users; --slack-bot-token-file/--slack-app-token-file/--slack-allowed-users/--slack-allowed-channels; --api/--no-api, --webhook/--no-webhook, --bind, --force. Retired --ssh/--no-ssh inputs are rejected. ONBOARD_* fallbacks and TTY prompts are defined in the parser/collect function. Missing noninteractive Telegram credentials fail rather than producing a fake live install. |
| Preserve settings on onboarding reruns | Existing regular config supplies defaults; --force updates provided values without resetting saved group/heartbeat/language/custom values or listener credentials/ports. Only missing example keys are added recursively. Hidden blank token input retains the existing token. Groups change only through an explicit option/environment value; no group question is added. New-install behavior and env/symlink/permission policies remain unchanged. |
| Sync-delegation question refusal and headless result guidance | Reject server-verified sync sub→main questions before main execution/session creation; continue work, report questions and avoid invented values. Async-send refusal uses the same instruction for sync mode; unknown mode and async question/fallback routing are preserved. Both tools carry delegation_id. Headless recipients receive no nonexistent-chat continuation hint, with compatible durable records. |
| Automatic implicit DM topic names | Default-on (`telegram_dm_topic_auto_name`), hot-reloaded naming of confirmed implicit DM topics. A one-shot title generation starts when a user message is received, runs beside the conversation and uses only the received user text/caption; the title is a subject noun phrase that excludes results. Unsuitable outputs (no topic, an answer, an echo of the prompt example) and API exceptions/timeouts can be retried on the next eligible user message, up to three received messages in total; counts persist, and stale eligibility after a restart stays blocked because an offline user edit cannot be ruled out. A JSON title enclosed in one complete Markdown code fence is accepted (json label optional, case-insensitive; CRLF/outer whitespace supported). The fallback is a safe message prefix or a neutral topic ID; user edit, disable and shutdown take priority, and the name cache is updated only after a confirmed success, which ends naming. Main and bot-backed subs use their own bot/home; group and unknown-origin topics stay unchanged. Telegram exactly-once delivery is not guaranteed. Titles are normalized once (NFKC, removal of combining marks, invisible/format/control characters and Hangul fillers) and outer decoration is stripped before the answer/echo checks, which also apply to the final cleaned and fallback candidates; a known English contraction is recognized before apostrophe removal so normal words such as Ill and filenames are accepted. Final titles are also checked with the credential detector after normalization/truncation, including fallbacks. A valid pending generation is kept beyond the message limit; a delayed DM creation name cannot replace a newer cache/project-root routing, and an observed user edit wins. Intake closes at stop/shutdown entry and owned cleanup is awaited even if stop is cancelled. Non-streaming process reaping is shielded across repeated cancellation (the original cancellation is preserved and no force-kill happens once the return code is known); an inline generation timeout keeps shutdown waiting through reaping, registry removal and temporary-cwd cleanup, so cleanup may extend the generation deadline. The answer/echo filters are quality safeguards with limits for artificial Unicode combinations, and users can edit odd titles; the credential boundary stays strict. |
| AI input receipt timestamps | Bot/bus intake time and any existing lock wait are added only to the CLI input of user, agent, result and question turns (including AI-bound button choices and user-started Named background turns). Queued user messages carry the receipt inside their queue block, and button/Named inputs keep their original arrival. First async-result and question timestamps survive durable retry/recovery (older records stay readable); lock waits are measured at actual acquisition, including FIFO predecessors while the lock appears unlocked, and exclude indicator/preparation time; agent-tool return metadata is annotated separately from unchanged bodies. Stored/display/log previews and system prompts stay clean; heartbeat/cron/webhook inputs are unchanged. |
| Task instruction receipt timestamps | Task submit/resume, including parent answers, receive AI-only intake time and the actual spawn-to-run wait. The numeric receipt/wait is persisted with a legacy first-recovery fallback, and a new resume resets its own receipt. The zone is `user_timezone`, resolved when the receipt is built (TaskHub accepts a zone string or a getter; AgentSupervisor registers getters over the main config as fallback and over each agent's live Orchestrator config), so a hot-reloaded `user_timezone` applies to the next task create/resume/parent answer without recreating the agent stack; missing or invalid values keep the UTC fallback. Raw task text/previews/system prompts and the existing concurrency rejection are unchanged. |
| Queued user message timing context | Telegram/Matrix/Slack messages that wait on an existing session lock carry send time, elapsed wait and arrival position into the CLI input only. Commands, buttons, cancelled entries and non-queued messages get no queue block. Routing and display/state/log previews keep the original text. No new setting or queue persistence. Foreground messages keep a single block, and the receipt is preserved when a user input starts Named background work. |
| onboarding writes | Writes root env, home config/provider/shared env and auth directories; secret/config files are private atomic replacements. Existing secrets are preserved unless forced; preserved secret symlinks are rejected. |
| login.sh | Retained script interface, with account-state persistence updates and repository .env home resolution. No arguments logs into available providers; claude [slot/--list/--repair], codex, gemini, grok and --help. Uses compose service resolution; Claude slots share projects/settings/skills as before. |
| Claude account-list persistence fix | After successful multi-slot login, accepting the TTY prompt now updates claude_accounts using proposed JSON passed through PROPOSED_JSON instead of competing for Python heredoc stdin. Other config keys and existing permissions are preserved; N/non-TTY skips the update, and update errors exit nonzero without the success notice. Synthetic PTY tests cover these paths. |
| Onboarding Telegram token validation | Trim hidden secret input at both ends (file input already trims). Both Telegram input routes require ASCII digits, colon and a nonempty letters/digits/underscore/hyphen suffix; internal whitespace or invalid format fails with exit 2 before writes, without echoing the token. Other messenger secrets are only trimmed. |
| Saved operator home resolution | login/logout/update use nonempty environment DUCTOR_HOME, then the repository-root .env DUCTOR_HOME key relative to the script, then ~/.ductor. The shared helper handles unquoted/single-quoted/JSON-double-quoted values without sourcing the file or expanding variables/commands. Synthetic Bash probes cover all three scripts and precedence paths. |
| Onboarding completion instructions | Show the saved bot language, build/start, tail bot logs, check Bot online, login using saved config provider, then status. Operator home is resolved automatically; README no longer requires an export after interactive onboarding. |
| logout.sh | Retained CLI interface; adds saved repository .env home resolution: no arguments or claude/codex/gemini/grok; claude --list/--disable SLOT/--remove SLOT or bare SLOT; --help. DUCTOR_CONTAINER controls its container name. |
| status.sh | Retained unchanged: no positional option parser; inspects container and CLI authentication state, using DUCTOR_CONTAINER. |
| rebuild.sh | Retained, unchanged: no option parser; compose build --pull with CACHEBUST, then up -d and ps; does not pull source. |
| update.sh | Retained maintenance flow with saved repository .env home resolution: no option parser; requires a clean tracked worktree, fetches origin/pulls ff-only, warns about in-flight files/tasks, prompts, then rebuilds/swaps. Its header saying nothing is lost is not an exactly-once delivery guarantee. |
| verify-clean-clone.sh | New verification entry point: REF; --repo PATH, --mode offline/live, --stage config/offline/build-extras/extras-exclusion/live-lifecycle/live-webhook-api/live-sub-agents, --keep (offline only), --live-token-file FILE. Active work triggers a second confirmation; declining leaves the new image built and the old container running. State file paths are passed as Python arguments, including homes containing apostrophes. |

## 4. Configuration, defaults and secret handling

| Change / interface | Behavior |
| --- | --- |
| Removed nested Docker settings | DockerConfig and AgentConfig.docker (enabled/image/container/build/mount/port/extras settings) are removed. Old JSON keys are ignored by model parsing but remain on disk through deep merge until removed manually. |
| Removed upgrade settings | update_check and notifications.upgrade_targets are removed; startup_targets remain. Remove stale keys only after backup. |
| Removed provider setting | cli_parameters.antigravity and Antigravity model/provider discovery are removed; Claude/Codex/Gemini/Grok remain. |
| Receipt notification default | New top-level interagent_notify_received:false. SubAgentConfig override is optional None/inherit; agents.json may opt in per receiving sub. --silent still suppresses a true receiver and remains valid when false. This is restart-required. |
| Runtime home example | The container config example now uses /ductor, matching the existing model default. Supervisor still merges each sub at /ductor/agents/NAME (an existing rule, not a new home-path feature). Host DUCTOR_HOME chooses the bind source. |
| Sub transport selection | Omitted transport resolves from own Telegram/Matrix credentials; both give Telegram then Matrix, neither gives headless. Explicit headless is accepted; explicit messenger without usable own credentials is rejected. No main Matrix account inheritance for a Telegram-only sub. |
| Matrix credential boundary | Configured password or access_token+device_id requires homeserver/user_id; matching saved credentials can supply credentials. Matrix store paths must stay inside the sub home and cannot be absolute, traverse .. or use symlinks. Account mismatch does not restore another account session. |
| Heartbeat baseline settings | The tracked baseline model has auto_targets:false and auto_target_window_hours:168, along with carried revision/dormancy state; automatic targets are enabled by default by the separate "Heartbeat automatic targets enabled by default" change below. |
| Container environment boundary | Root env carries DUCTOR_HOME/DUCTOR_EXTRAS/bind settings. Home .env carries provider/service keys; .env.shared supplies only the bot/browser common token and timezone. Compose mounts these explicitly. |
| Secret inputs and private writes | Onboarding takes messenger passwords/tokens through file arguments or hidden prompts, creates a browser token, and writes private files under umask 077. Tool credentials live in the separate home secrets.env described in the next row. |
| Shared secrets store | The home secrets.env (mode 0600) holds credentials that tools read at run time; onboarding creates it empty only when it is missing and never touches an existing file. It is not injected into CLI runs: a tool calls load_secrets("KEY") from tools/_secrets.py, and a value already in the environment wins. The framework gives every CLI run (interactive and one-shot, main and sub-agents) DUCTOR_SECRETS_FILE pointing at the main home's store unless one is already set. Provider keys that a CLI reads when it starts stay in .env. The live-sub-agents stage of verify-clean-clone.sh checks the whole path with synthetic keys. |
| Build-time versus runtime features | Runtime enabled features must be present in DUCTOR_EXTRAS at build time. OpenSSH is unconditional; Matrix/Slack/API libraries are feature extras. Sub dependency errors exclude only that sub; main missing dependency exits3. |
| Trusted CLI environment | Provider secrets are loaded from explicit CLIConfig.ductor_home, not an untrusted project working directory. Framework DUCTOR_HOME/agent/route values override provider extra_env; absent route values are cleared. This does not globally override inherited HOME. One-shot routing normalization runs after merges. |
| Routing metadata names | result_origin and broadcast_ref are new request/task/result/envelope metadata, not new user config keys. Tools carry DUCTOR_RESULT_ORIGIN/DUCTOR_BROADCAST_REF without reusing generic envelope Origin. |

## 5. Runtime behavior changes

| Change / interface | Behavior |
| --- | --- |
| Busy Telegram buttons and result-injection typing | Ordinary AI-bound buttons use the existing queue notice and cancel control, reply in the same topic, and suppress duplicate clicks until completion or cancellation cleanup; shutdown never executes a waiting choice and callbacks are not replayed. Result injection shows best-effort Telegram/Matrix typing; Slack, headless and private task-question answers show none. Delivery protocol, message ingress and journal policy are unchanged; dedup is memory-only. |
| Headless delegated agents | HeadlessBot participates in the bus/registry and observer wiring without a messenger. Its cron/heartbeat/webhook observers are disabled; headless is sub-only. |
| Async sender/receiver restrictions | Headless asynchronous outbound requests and async results addressed to headless are rejected. An async sender must have a registered result receiver. Incoming delegated turns reject async onward sends even for a messenger sub; synchronous onward calls remain allowed. |
| Origin context on delegation | Original chat_id/topic_id/transport travel through CLI environment, ask tools, API parsing, tasks/results and named-session scoping. This prevents context-bearing follow-ups from falling into a context-free session. |
| Receipt sender and route | A received-task notice, if enabled, is sent by the receiving sub own notifier to the original route. There is no main-bot fallback. The configuration gate is server-side, so old tool callers also obey it. |
| Main handles every async outcome | Success, failure and interruption results are injected into the requesting main session; only main final output is delivered. Empty reports and injection exceptions do not transmit sub raw text; the result remains retryable. |
| Checked delivery outcomes | Messenger callbacks return meaningful delivery status; Matrix/Slack checked send helpers and Telegram IDs decide acknowledgment. Mismatched transports cannot silently fall back to another messenger for an IA result. |
| Failure ledger | Private failures.json normalizes/hash-keys request series, counts a task once, expires after 24h and resets on success. Counts survive save failure in memory, not a restart if the update was unsaved; it is a prompt guard, not a hard delegation limit. |
| Durable requests and stages | Persist accepted async requests, complete results, route, main_response and delivery stages. Restart recovery distinguishes a truly interrupted request from a completed/persisted result. |
| Storage boundary | Durable records use validated task IDs and hashed target paths under private interagent directories, with atomic writes and symlink checks. Corrupt bytes are quarantined; other tasks continue. |
| Retry stages avoid reinjection | Already-injected main text is reused for retry. Unconfirmed deliveries are parked instead of discarding the result; shutdown cancellation parks available results. |
| Chunk acknowledgment | Progress records bind delivered chunks to the main text hash and transport chunk scheme. Telegram/Matrix/Slack resume confirmed progress, requiring acknowledgment IDs/list results instead of pretending file sends succeeded. |
| Telegram IA formatting | IA file/button parsing precedence and chunk schemes preserve normal file uploads and buttons through retries. The unfinished-marker case is a known limitation. |
| Ambiguous Telegram sends | Avoid a blind immediate IA resend after uncertain network delivery; retained records permit subsequent handling but cannot prove whether a remote send happened. |
| Readiness by generation | Main generation/injector readiness gates initial and stored delivery. Fatal generation paths clear readiness; missing readiness parks results. |
| Readiness replay and concurrency | Agent registration/readiness rescans stored records, recovers inflight first and claims each task to avoid concurrent ready-cycle replay. Overlapping events trigger another scan. |
| Periodic stored-result delivery | Persist retry attempts/next_redelivery_at; periodic supervisor scans respect backoff, with a default 300s interval and exponential delay capped at 6h. Readiness requests can override the scheduled wait. |
| Recovery preserves actual result | When memory has the actual finished result, recover it instead of synthesizing interruption. Acknowledged in-process delivery survives record cleanup failure; persisted backoff also applies to partially parked completed inflight work. |
| Cron/background routing | Cron/webhook one-shot and background tasks propagate the original chat/topic/transport rather than lose topic or default to a main DM. API CLI origin is marked while legacy API/TG session identity is retained. |
| Cron broadcast isolation | Broadcast-origin IA results inject into a new isolated session per result, do not resume/overwrite the default DM active session and preserve broadcast_ref during re-delegation. |
| Broadcast delivery contract | IA final reports broadcast through each configured transport recipients. Zero recipients/any failed recipient is failure and retained for retry; partial retry is currently whole-broadcast, not failed-recipient-only. Regular cron failed-transport retry is a separate change. |
| Sub hot reload and exclusion | Credential changes across any active sub transport trigger reload; invalid/missing-dependency subs stay excluded even on manual starts, but corrected definitions are rechecked. start/restart outcomes reflect actual registration. |
| Safe definition diagnostics | Validation/merge errors use item index, exception type and sanitized field locations, not raw input/name/traceback. Discovery labels stay private until merge succeeds; inactive optional feature blocks do not give false dependency hints. Valid sub names may still be shown. |
| Command-log assignment redaction | Environment assignments outside a small visible-key allowlist are masked by _log_redact.py. This is not a promise to redact arbitrary positional text or every application log. |
| Memory flush locking | Restores session locking inside flush/compact because scheduled flush can run outside the turn lock; headless observer wiring shares the bus lock pool. |
| Bundled skill links | Migrate managed bundled skill copies to package links without clobbering user-owned copies; recover interrupted migration and protect external symlinks. |
| Internal API bind | Inter-agent internal API binds loopback instead of switching to all interfaces when docker.enabled. This is separate from optional direct API and webhook bind configuration. |
| Browser token source | Control server now fails before listen if BROWSER_TOKEN is empty; it no longer runs unauthenticated. With a token, non-health routes require x-browser-token and reject missing/wrong tokens with 401, while /health remains exempt. Shared env supplies the same token to bot and browser. |
| Allowlist rejection diagnostics | Telegram/Matrix/Slack log INFO chat type/chat/user/topic metadata for actual allowlist denials, never message content; same retained chat/user pair at most once per 600s, with up to 1,024 pairs per logger and oldest-entry eviction. Existing authorization/mention policy is retained. |
| Telegram command buttons | Recognized ductor slash-command callbacks enter the same typed-command handlers/filters with selected-button marking preserved. Unknown slash commands remain AI prompts. |
| Restart guidance matches config reload | Remove retired docker and synchronize bundled RULES restart-required keys with ConfigReloader, retaining /restart guidance; unknown keys require restart. |
| Immediate foreground login guidance | Resolve session provider and freshly check auth before ordinary/streaming and foreground named-session user CLI calls. Unauthenticated turns do not execute CLI and reply with localized host ./scripts/login.sh provider instructions. All foreground transports share it; inter-agent/cron/webhook task auth behavior is retained. |
| Locale-based onboarding UI language | First-install precedence: --language > ONBOARD_LANGUAGE > first nonempty LC_ALL/LC_MESSAGES/LANG language part > en. On reruns, saved language precedes locale detection. Bundled language codes are discovered from i18n; unsupported server locale falls back to en, unsupported explicit values fail before writes. Question 5 and completion notice show default/saved language; config language is written, prompts stay English. |
| Delegation-only agent guidance | Bundled workspace/agent-tool and generated main identity descriptions distinguish headless workers with no direct chat/token from bot-backed subs; document create_agent.py --transport headless and main-mediated results. Result notices for registered headless recipients contain only the processing-session sentence; bot-backed recipients keep the chat continuation hint. |

## 7. Known limitations

- **Interrupted-task notice transport.** The notice about a task a restart cut off is sent through the agent's primary transport. In a multi-transport agent it does not go back to the transport the task was started from (the task record has no transport field). Telling the parent is tried once per start and given up after three failed tries.
- **Update journal scope.** The Telegram update journal keeps message updates only (edited messages, member changes and other kinds are not replayed), is Telegram-only, and covers what the server still holds: Telegram keeps unconfirmed updates for 24 hours, and the journal drops waiting updates after the same time. If the journal file cannot be saved, the reader waits and retries (and so does not confirm the update to the server), and an update that cannot be marked as started is not run until the next start. A button press is never replayed. A message sent while a stop is already in progress (for example a second `/restart`) has not been received yet, so it is processed once after the next start.
- **Matrix sub-agent stop.** A Matrix bot cannot end `run()` on request (the sync loop runs in the supervised task), so stopping a Matrix-only sub-agent always cancels it. A cancelled task that does not finish within the wait (10 s, at least 1 s once the shared budget is used up) is left behind and logged; the stack shutdown then runs while it may still be cleaning up.
- **Unfinished button marker.** An unclosed outer button marker can leave a subsequent valid file marker at top level, so the file can be uploaded. Older non-IA cross-nested handling is out of scope.
- **Parent symbolic links and a race.** Parent symbolic links of config/auth paths may be followed, and a race remains between path inspection and chmod. Direct and dangling secret links are rejected separately.
- **Naturally exited sub-agent.** A stopped health task may leave a registered stack, and a plain start then reports that the sub is already running. `agent_stop` followed by start re-registers it and retries parked results.
- **Duplicate result after a double failure.** If a storage read/move fails, the in-memory delivery succeeds and a restart happens before cleanup, the result may be sent or injected again. In-memory done flags do not provide exactly-once delivery across that restart.
- **Partial broadcast retransmission.** If an inter-agent broadcast fails for some recipients, the whole broadcast is retried and may duplicate recipients/transports that already succeeded.
- **Receipt notice access.** A receiving sub with receipt notices enabled sends them with its own bot; without access to the origin group the notice fails, and there is no main-bot fallback. The default is off, and result delivery is separate.
- **API and Telegram session sharing.** API and Telegram session identity can remain shared for the same chat ID; API token holders choose the chat.
- **Delegation-question fallback boundary.** A Named source or an unconfirmed background source immediately uses a separate Named Session without resuming unrelated foreground state. A busy foreground source lock after 60 s, an unavailable resumable source session or unidentifiable delegated provenance uses the same fallback. It does not automatically resume the source conversation: a header supplies the original chat/topic/name when known, the source session key/provider ID, the task/request ID, a safe preview of up to 200 characters and confirmed history/metadata paths; unavailable fields stay unconfirmed. Known credential/authenticated-URL formats suppress the entire request preview; completeness for arbitrary secrets and semantic filtering are not guaranteed. Verified synchronous questions to main are rejected before invocation or session creation. Context-free and unknown-mode messages keep the earlier behavior. The sync-bus request deadline is 300 s; cancellation reaping has no separate fixed cleanup time limit.
- **Prompt-argument residuals.** Forcing a worker wait can race with cancellation of the Claude prompt-file cleanup. There is no per-user task isolation (an existing agent-level permission). Explicitly configured raw CLI arguments and Grok `--rules` / `--system-prompt-override` stay in argv.
- **Named background on Matrix/Slack.** Matrix/Slack Named background completion is not recorded in the Named registry (state, session id, message count) while Telegram records it.
- **Memory lint skipped files.** A link inside the memory root that is skipped is reported by its root-relative name (never the target path or content) and counts as a problem, so the weekly agent turn starts for it. Skipped pages are invisible to search, so the user should know.
- **Lanes, cycles and the Matrix restart marker.** Cycles deeper than a session talking to itself (A waits for B while B waits for A) are not detected and end by timeout. Lanes share the sub's workspace, memory files, provider login and rate limits; the git worktree and file split are a recommendation, not enforced. A Matrix restart marker created by hand while the bot runs marks the shutdown only when the bot's run ends (the Matrix watcher cancels its sync task without going through the restart helper). In an artificial boundary the async re-check after admission restarts the wait budget (nothing runs and no reservation is left).
- **Sub-agent restart while a foreground turn is finishing.** When only a sub-agent is restarted (`stop_agent`, the sub restart exit, a crash rebuild) while one of its foreground turns is finishing (right after the answer, for example during prompt-file cleanup) and a new turn of the same sub starts right after the restart, (1) the completed session id of a manual foreground inter-agent resume is not saved (its old Named registry is already closed; a `write skipped` warning is logged) and stays empty, and (2) the late finish of the old foreground turn overwrites the new stack's session id in `sessions.json` (this path existed before). The range is one session id/state; the next request may start a new session.
- **Recovery notices of secondary transports.** The primary transport announces all interrupted turns after a restart, also those of a secondary transport of the same agent; such a notice is sent through the primary transport and may not reach the chat of that transport.
- **Cron exception notice after a mid-run definition change.** When a cron job is deleted or re-targeted while it runs, the run fails with an exception, and sending the error notice to the original destination also fails, the notice is not kept for a later retry: it is neither recorded on the changed definition nor resent to the new destination, so that one notice is lost.
- **Cron `in_session` and `inject` results.** The `last_run_status` of an `in_session` cron follows the delivery of the injected turn's reply, not the quality of the work; when the turn failed (timeout, error, empty reply) only a short note is sent, and the reply is not resent and the job is not re-run. An `inject` reply still carries the existing `TASK: <title>` header of the cron transport output.
